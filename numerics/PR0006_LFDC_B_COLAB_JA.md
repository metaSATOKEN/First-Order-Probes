# PR-0006：LF-DC警報予算 B25 — Colab実行手順

研究条件は[PR-0006](../audits/prereg/PR-0006_lfdc_alarm_budget_confirmation.md)に固定済み。本番データはまだ生成していない。今回渡すのはユーザー実行用セルであり、ローカル試験の合格は科学的な成績ではない。

## 最初の実行

1. ColabでGPUランタイムを用意する。A100など、float64を実行できるNVIDIA GPUを使用する。
2. [1セル用Python](colab/pr0006_lfdc_budget_b25_one_cell.py)の**全文を1つのコードセルへコピペしてRUN**する。または[1セルNotebook](colab/pr0006_lfdc_budget_b25_one_cell.ipynb)をColabへアップロードして実行する。
3. 初回は先頭設定を変更しない。`RESTORE_ZIP = ""`、`AUTO_DOWNLOAD = True`のまま。Drive接続も入力ZIP選択も不要。
4. ブラウザの複数ファイルの自動ダウンロードを許可する。実行中に届くZIPを保存する。

既存の数値カーネルを分離環境で使う。NumPy 2.1.3、SciPy 1.16.3、CuPy CUDA12x 14.2.0に固定し、既存ノートブックのPython環境を直接更新しない。依存導入後に44条件×3記録のCPU/GPU float64技術照合を行い、通れば本番へ自動的に進む。照合不一致なら停止する。CPUへの自動切替やfloat32化はしない。

処理の目安は以前と同程度の機材で**50〜90分**。環境構築、圧縮、ダウンロード、Colab側の混雑により増える。入力乱数の生成はCPU側で、GPU性能だけでは所要時間は決まらない。45分ごとの人工停止はない。累積worker能動処理は4時間上限で、上限に達した場合はPARTIALを保存する。単なる再RUNでこの上限をリセットしない。

## ZIPの保存方法 — 今回の重要な変更

**通常は5本のデータZIPと、1本の小さい最終索引ZIPを保存する。最後のZIPだけでは全rawは揃わない。**

| ZIP名の部分 | 中身 | 保存上の扱い |
|---|---|---|
| `SHARD_01_COMPLETE` | 反復00–04のraw・判定、そこまでの小集計／索引 | 保持 |
| `SHARD_02_COMPLETE` | 反復05–09のraw・判定、そこまでの小集計／索引 | 保持 |
| `SHARD_03_COMPLETE` | 反復10–14 | 保持 |
| `SHARD_04_COMPLETE` | 反復15–19 | 保持 |
| `SHARD_05_COMPLETE` | 反復20–24と最終集計 | 保持 |
| `COMPLETE_INDEX` | 全25反復の小集計、全体結果、各データZIPのハッシュ付き索引 | 保持。全rawの代わりではない |
| `PARTIAL` / `TECHNICAL_FAILURE` | 進行中の小実験のraw・判定＋それ以前の小集計／索引 | 途中復旧の入口。完了シャードも保持 |

5反復終了ごとにZIPを作り自動DLを要求する。進行中の小実験でも前回梱包から15分を超えたら、次の安全なチャンク境界で途中ZIPを作る。過去の別シャードのrawは毎回詰め直さない。同じシャードの途中ZIPは、そのシャード内での復元用スナップショットであり、前の途中ZIPとの増分差分ではない。

各ZIPは事前展開量800 MB以下、**実ファイルが十進1,000,000,000 bytes未満**のゲートを通す。5反復で上限を超えれば、科学条件を変えず固定の1反復単位へ分ける。このときは`_REPxx`付きの全パートを保存し、復旧の入口には最後のパートを使う。単一反復も上限を超えれば停止し、元ファイルを残す。

17列float64と判定ビットの5反復分は、未圧縮の配列下地で約400 MB。実際のZIPサイズは保存ログ・メタデータ・圧縮率で変わるため、実測サイズゲートを最終判定に使う。停止時のZIPと最終索引にも同じ上限を適用する。

## 再開

### 同じランタイムが残っている

**同じセルをもう一度RUNするだけ。** 保存状態を検証して既存チャンク・完了反復を使う。ZIP選択は出さない。`RESTORE_ZIP`に前回の値が残っていても、検証済みの現ランタイムを優先し、上書き復元しない。

### ランタイムが消えた

新しいGPUランタイムへ、手元の**最新の進行ZIPを1本**アップロードし、この同じセルをRUNする。ColabのFilesに既にあれば自動選択する。手動ファイル選択にしたい場合だけ、セル先頭を`RESTORE_ZIP = "UPLOAD"`にする。特定パスを設定する方法も使える。

復旧ZIPには、現在のシャードのrawと、過去完了反復の小集計・証拠ハッシュがある。過去rawがランタイムにないことを明示して引き継ぎ、過去の科学試行を再生成しない。最終索引だけからの復元は完了状態・集計の復元であり、失ったrawを作り直す機能ではない。

同じcell/run/specだけを受理し、異なる実行が複数アップロードされている場合は曖昧な自動選択を止める。ZIP中のコードは証拠として照合するだけで、実行はセルに埋め込んだソースから行う。

突然のVM消失では、**最後に手元へ保存できたZIP以降**の状態は回収できない。保存済みIDの重複計上は避けるが、失われた未保存チャンクは同じ乱数IDから再計算する。サービス側の切断そのものを防ぐものではない。

## 自動DLが開始しない／止まった場合

原データ・完成ZIPは自動削除しない。Colab左側のFilesから、出力表示の`archives`フォルダ（通常 `/content/lfdc_budget_pr0006_v1/archives/`）を開き、対象ZIPを右クリックしてダウンロードできる。

ブラウザ側のDL完了はコードから観測できない。`request_sent=True`は要求が送れた意味で、保存完了の保証ではない。`final_archive_created=False`の場合は完了した科学データがあっても最終梱包が未完了なので、ランタイムを消さず出力を共有する。

`TECHNICAL_FAILURE`やハッシュ不一致を、設定変更・種の差替えで無理に回避しない。ログとZIPを残して原因を点検する。

## 何を比較し、何を変えないか

25外側反復、正常10群・故障33・時間反転対照1、固有13,749,700記録。固定LF射影の3尾に対しW0／WP／WG／W+／W−の5固定配分と旧LF0を比較する。主1%、補足0.1%。正常ref→射影固定→正常cal→閾値固定→評価の順で、評価データによる配分・方向・閾値の選択は行わない。

全25反復後に、枝・OR・拾得／損失・見逃し・誤警報・不成立、正負差、F/C差を集計する。主25比較・FPR216系列の区間はカードどおり。結果が不鮮明でも今回のデータを見て50反復へ継ぎ足さない。次の追加確認や論文採用は別裁定。
