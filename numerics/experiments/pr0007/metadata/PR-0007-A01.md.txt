## 2. 配布単位とサイズ（本体§2.7–2.8の該当部分を置換）

通常完走時は**5反復で1データZIP、計5データZIP＋小さい最終索引ZIP**。反復IDは0始まりで、次の範囲を固定する。

| データZIP | 収録する反復ID |
|---|---|
| SHARD_01 | 00–04 |
| SHARD_02 | 05–09 |
| SHARD_03 | 10–14 |
| SHARD_04 | 15–19 |
| SHARD_05 | 20–24 |

各データZIPはその5反復だけを含む非累積形式。前シャードのraw／判定を次シャードへ入れない。最終索引は全partの名称・反復範囲・サイズ・SHA-256・転送状態を収録し、全データを再梱包しない。

| 5反復分の主要未圧縮配列 | bytes |
|---|---:|
| raw統計 | 296,746,560 |
| packed判定 | 92,400,000 |
| 合計 | **389,146,560**（約389.1 MB） |

モデル・閾値・索引等は別途加算する。この数はZIP実サイズやピークRAMではない。

容量規約は**目標600,000,000 bytes未満、梱包前の保守的見積り800,000,000 bytes以下、完成ZIPは厳密に1,000,000,000 bytes未満**。旧「目標100 MB／上限128 MB」は今回の配布規約から外す。目標600 MBを超えただけでは科学試行を打ち切らず、見積り・実サイズを記録する。

見積りが800 MBを超える場合は先にpart分割する。梱包後1 GB以上ならそのZIPを配布せず再分割する。まず反復境界、必要なら当該反復内のコミット済みチャンク境界で切り、各partの実サイズを検査する。記録ID・種・科学件数は変えない。単一チャンクでも上限に収まらない場合はデータを保持して容量不成立を報告し、黙って削減しない。

## 3. 保存・再開・転送（維持する事項と変更点）

- raw・判定のチャンク保存、整数逐次集計、反復ごとの完了検証は維持する。5反復をRAMにまとめて保持する変更ではない。
- 通常の自動DLは**5反復のシャード完成時**。各反復完了だけではデータZIPを配布しない。チャンクと反復の保存・再開可能性は、DLの間隔とは別に保つ。
- シャード進行中に前回梱包から15分を超えた場合、または停止時は、未配布のコミット済み分から非累積PARTIAL delta ZIPを作る。これらも上記サイズ規約に従う。したがって**中断・長時間処理・容量分割時には5個より増える**。通常完走の基本セットを5データZIP＋索引とする意味である。
- シャードの最終ZIPと同じシャードのPARTIALが重複する場合は、IDとハッシュで照合し二重計上しない。完了済みの前シャードをPARTIALへ累積しない。
- ディスクからの逐次梱包、原raw／原ZIPの保持、同時1転送、受信資源の解放、計算／転送／保存開始／利用者ディスク確認の状態分離を維持する。ブラウザに複数ZIPを一括保持させない。
- Driveなし、生存ランタイムの自動再開、消失後のZIP復元、未送信partだけの再送、通常1 RUN完走、45分の人工停止なしを維持する。DL遮断時は転送を保留し、計算・保存は既存ディスク予算内で継続する。

## 4. 科学条件は変更しない

25反復、6正常群／18故障、正常cal3件数、3故障種×2混入数、固定5配分＋LF0、ref/cal/eval分離、入れ子・置換位置、主8比較、FPR792系列、探索的交差1,296セル、全10,909,800生成記録／693,000,000判定、master・役割ID・64記録乱数ブロック、指標・推論・欠測／停止規則は本体どおり。

科学的な1反復は引き続き独立な外側反復。5反復を一つの統計反復に数えない。実験ID／乱数名前空間を変更せず、将来の配布・run manifestには**本体とA01両方のハッシュ**を含め、I/O改訂を識別する。実装・配布セルはまだ存在しない。

## 5. 受入試験の差分と現状

本体§4の科学的・数値的受入条件は維持する。I/O試験は1反復ZIP／128 MB境界の代わりに、次を確認する仕様へ変更する。

1. 5シャードが反復00–24を欠け・重複なく分割し、最終索引に全partが載る。
2. 5反復の配布を待たず、保存済みチャンク・反復から再開できる。PARTIALと最終シャードの重複復元で二重計上0。
3. 見積り800 MB超／完成1 GB以上で分割し、各partは厳密1 GB未満。科学条件と原データを保持する。
4. Colab／Macで約389 MBの主要配列を含むシャードの転送時間・保持資源・実サイズ／ハッシュを確認し、同時転送最大1を点検する。

今回確認したのは配列量の乗算と5シャードの反復分割、固定資料の同一性、導線だけ。実装、ZIP生成、ブラウザ転送の実機試験はしていない。元カード・元検証・原データ・論文は保持。次の作業範囲は実装・技術点検の明示承認を待つ。
