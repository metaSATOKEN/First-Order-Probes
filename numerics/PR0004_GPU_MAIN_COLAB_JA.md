# PR-0004 GPU本番：LFと既存4方式、50反復

研究条件の正本は[PR-0004](../audits/prereg/PR-0004_linear_fusion_source_shift_gpu.md)。実行はユーザーがColabで行う。こちらで本番データは生成していない。

## 1. 起動

1. Colabで**GPUランタイム**を用意する。A100でも、前回のRTX PRO 6000でもよい。機種は自動記録し、起動ごとにfloat64のCPU/GPU照合を行う。
2. [1セルPython](colab/pr0004_gpu_main_one_cell.py)の全文を、コードセル1つにコピペして1回実行する。または[1セルNotebook](colab/pr0004_gpu_main_one_cell.ipynb)をColabへ読み込む。
3. `RESTORE_ZIP = ""`、`AUTO_DOWNLOAD = True`のままでよい。**初回に点検ZIPを選ぶ必要はない。Driveにも接続しない。**
4. ブラウザの複数ファイルのダウンロードを許可しておく。10・20・30・40反復で復旧用`PARTIAL` ZIPが落ちてくるが、**そのまま処理は続く。再RUN・ZIP選択は不要。**
5. 50反復の生成と集計が終わり、`COMPLETE` ZIPが出たら保存する。ファイル名は`linear_fusion_pr0004_v1_<run>_COMPLETE_<id>.zip`。このZIPを返却すれば分析できる。

新セルはPR-0003の点検セルとは別実験。点検やPR-0002のZIPを復元元に指定しない。新しい実行名で始まり、既存の実験ファイルは変更しない。

## 2. 時間と容量

| 項目 | 見込み・上限 |
|---|---|
| 科学的記録 | 33,499,400、外側50反復 |
| 比較 | M・CR・B・J・LF。LF-Dは副比較 |
| 通常計画 | **2.5〜4時間**。機種・CPU・ディスクで変わる |
| 外挿の内訳 | 生成＋スコア約101分。学習・校正・集計・ZIP等を加えた計画枠。新本番系統の実測ではない |
| 安全停止 | ワーカー累積6時間。45分ごとの停止はない。依存導入最大20分、最後のZIP回収最大30分は別枠 |
| 生スカラー | 17列float64、約4.243 GiB。圧縮後のサイズはまだ未実測 |
| 最終ZIP上限 | 6 GiB。展開証拠16 GiB、復旧ZIPの累積保存40 GiB、新規開始時の空き64 GiB |

前回の速度はRTX PRO 6000＋EPYC9B45で測ったもので、A100の実測ではない。GPU内の40倍以上の計算短縮を、処理全体の倍率としては使っていない。入力生成はCPUのまま。短窓512、他4096の計算バッチで全てfloat64。

復旧用ZIPはその時点までの全量なので、後半ほど大きくなる。複数回のダウンロード総量は最終ZIPより多い。元証拠や過去ZIPをコードが自動削除することはない。ブラウザが自動DLを止めても、ZIPはColabのFilesに残る。

## 3. 中断したとき

**ランタイム内に保存状態が残っている場合：** 同じセルをそのまま再実行する。既存ファイルを検証し、完了チャンクと完了した反復解析は再利用する。ZIP選択は出ない。

**ランタイムが消失した場合：** 最新のPR-0004 `PARTIAL` ZIPをColab左のFilesへアップロードし、その後で同じセルを実行する。自動検出・全ファイル検証・復元後に続行する。数GBになるため、通常はFiles経由を推奨。例外用に`RESTORE_ZIP = "UPLOAD"`や絶対パス指定も使える。

別runのZIPが複数あれば、自動で一つを選ばず停止する。その場合だけ`RESTORE_ZIP`に続行したいZIPのパスを指定する。復元後は空文字へ戻して再実行する。現在の状態への上書き復元は拒否する。

`TECHNICAL_FAILURE`や予算超過なら、ZIPとログを残して共有してほしい。標本数・精度・閾値・総予算を変更して通さない。6時間の累積上限は再RUNやZIP復元でリセットされない。

サービス側の切断は防げない。Driveなしなので、VM消失時は**最後に手元へ保存できたZIP以降**の作業を失う。最新ZIPから同じID・種で再計算するが、消失した時間の正確な累積は復元できない。ダウンロード要求の成功と、ブラウザの保存完了は別である。

## 4. ZIPの中身と読み手

- `manifest.json`／`specification.json`／`sources/`：実行・条件・カード・コード・依存固定。再開時と返却監査で読む。
- `chunks/`：全17列、記録ID、役割、条件、値ハッシュ、生成計時。監査で学習・校正・評価を再構成する。
- `waveforms/`：事前指定した反復0・各条件先頭3記録の生入力と波形。全波形を保存したものではない。
- `preflight/`／`sessions/`／`launches/`：CPU/GPU一致、実機環境、失敗・再開・時間・メモリ。
- `analysis/repeats/`：正常参照モデル・順位表・校正閾値・全判定ビット・拾得損失・32/64パターン・飽和率。確定反復を`done.json`で識別する。
- `analysis/summary.json`：主要12比較、FPR140系列、全条件率、LFの得失、更新方針差。**率・差は0〜1基準**で、%／ppへ換算する場合は100倍。
- `analysis/costs.json`：生成・転送・計算・保存・学習・校正・評価・集計の時間。追加3モーメントはGPU計算に含み、単独寄与は未分離。
- `ARCHIVE_INDEX.json`：全収録ファイルのサイズ・SHA-256。ZIP作成・検証時間はZIPコメントにも保存。自身のハッシュやDL後の状態を再帰的に収録しない。

正常源変化に対する警報を故障検出成功と数えない。主表は同じ公称1%による手順比較であり、実測FPRを事後に揃えた表ではない。負のCRや補正分散、不利な結果も保存する。50反復が揃わない場合に確認実験の完了とは表示しない。
