# PR-0003：CPU/GPU float64実装・運転点検

2026-10-17。分類：**実装・運転試験**。LFの科学的性能比較ではない。
ユーザーはCPU/GPU比較点検版の実装、Colab 1セル、Driveなし、保存・再開・ZIP自動DLを依頼し、Colabの実行は本人が行うと指定した。以下はその範囲内の点検仕様。未採択の33,499,400記録の本番案を承認・登録したものではない。

## 1. 変更・実験の1行

同じfloat64入力に対するSciPy一次フィルタとCuPy/CUDA一次フィルタの出力、17スカラー、符号付きM/CRを照合し、計算単体と生成・転送・保存込みの時間を対応比較する。

参考：[NB06一セル](../../docs/OMITTED_MATERIALS.md#item-2f6bf3d58f29)の環境隔離、CUDA診断、計時境界、原子的保存、証拠回収を参考に新規実装する。LLM、HF認証、低精度量子化、Triton Attention、105分停止は移植しない。

## 3. 予想（結果より先に確定）

- H1：指定したfloat64許容差内で全比較が一致する。全タスクの一致で支持、1値でも超過なら反証。GPU初期化不能等は未成立で、技術失敗を別計上する。
- H2：大バッチGPUで計算単体の短縮余地がある。倍率は予想しない。条件別3反復中央値を報告し、同一環境でGPU/CPU < 1ならその条件で短縮、>=1なら非短縮。環境が分かれ反復が不足した条件は未確定。
- H3：計算単体の利得が転送・CPU乱数生成・保存で縮む場合がある。各費用と全体比を報告する。全条件一律のGPU優位は仮定しない。
- 運転試験：同一ランタイム再開、ZIP復元、破損・仕様違い拒否、同時起動拒否、完了済みタスク非再生成、最終DL経路を検査する。モックとColab実測を区別する。

## 4. 昇格・停止条件

数値不一致は速度にかかわらずGPU本番採用不可。数値全件合格後、条件別全体時間・環境・容量・復旧結果を人間が確認して採否を決める。点検完了はLF科学実験の開始条件を満たしたという意味ではない。CPU/GPUの性能選択は今回の技術点検で行ってよいが、科学的評価標本を使って方式を選ばない。

選択肢：A＝今回のCPU対GPU点検（推奨・今回依頼で採択）、B＝CPU継続（GPU全体利得なし/数値失敗で再検討）、C＝GPU乱数・専用融合カーネルまで拡張（転送/CPU乱数が律速と実測され追加承認された時）。この版でCへ自動進行しない。
